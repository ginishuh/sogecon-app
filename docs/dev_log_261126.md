- Fixed: 직접 생성이 사전 확인 뒤 잠금 없이 INSERT해 동시 요청·가입 승인과 경쟁하던 문제. 승인과 같은 advisory lock을 같은 순서(학번 키 → 소문자 이메일)로 잡는다. flush 단계의 UNIQUE 위반도 500 대신 409로 바꾼다.
- Fixed: 관리자 회원 정보 수정(`PATCH /admin/members/{id}`)과 본인 수정(`PUT /me/`)의 이메일 중복 확인이 저장 값의 대소문자·앞뒤 공백을 무시하지 못하던 문제. 소문자 이메일 advisory lock 후 다른 회원만 대상으로 대소문자·공백 무시 비교한다. 자기 이메일을 대소문자만 바꿔 저장하는 것은 허용된다. 두 수정 경로는 학번을 바꿀 수 없어 학번 키 잠금은 필요 없다.
- Changed: 사용처 없는 `members_service.create_member`도 같은 규칙을 적용했고, 이메일 충돌 코드를 `member_exists`에서 `member_email_already_in_use`로 맞췄다(HTTP 경로 없음).
- Notes: 같은 학번 키의 대기 신청이 있어도 직접 생성은 막지 않는다. 직접 생성한 회원은 `active`라 그 신청을 승인하면 `409 signup_member_exists`가 되어 회원 행이 둘 생기지 않는다.

## 독립 리뷰(Codex) 반영

- Security (P1): 안내 메일이 신청서의 이메일로만 나가, 승인 뒤 관리자가 회원 이메일을 고쳐도(오타, 다른 사람의 주소) 재발급·재발송이 옛 주소로 활성화 링크를 보내던 문제. 수신 주소를 활성화될 회원(학번 완전 일치, `active`)의 현재 이메일로 바꿨다. 회원이 없거나 활성이 아니거나 이메일이 비면 보내지 않고 `activation_member_missing`·`member_not_active`·`email_recipient_missing`으로 알린다. 수동 발송·승인 자동 발송·재발급 자동 발송이 같은 판정을 쓴다. 활성화 전 회원은 로그인할 수 없으므로 이 시점의 회원 이메일은 관리자만 바꿀 수 있다.
- Fixed (P2): 재발급이 발급을 커밋한 뒤 재조회해 응답을 만들어, 재조회 실패 시 발급만 남고 500이 되던 문제. 신청 행을 `FOR UPDATE`로 잠가 상태를 판정하고 응답 스냅샷을 커밋 전에 확보한다(승인과 같은 방식). 사용처가 없어진 `signup_service.reissue_signup_activation_token`은 지웠다.
- Fixed (P2): 발송 판정이 같은 세션에 남은 신청 행 값을 써, 그사이 다른 세션에서 활성화가 끝나도 메일을 보내고 `sent`로 보고하던 문제. 발송 직전에 행을 다시 읽어 `approved`가 아니면 보내지 않는다.
- Fixed (P2): 본인 수정 화면은 이메일을 항상 함께 보내는데, 과거 자료에 대소문자만 다른 이메일을 가진 회원이 둘 있으면 다른 항목만 고치는 저장도 409가 되던 문제(이번 변경으로 생긴 회귀). 주소가 그대로인 저장(대소문자·앞뒤 공백 무시)은 다른 회원과 비교하지 않는다.
- Changed: 관리자 화면이 다시 보내도 해결되지 않는 발송 실패(회원 비활성·회원 없음·이메일 없음·메일 미설정)의 사유를 알려 준다.
- Tests: 동시 직접 생성 테스트 2건이 먼저 시작한 쪽이 이긴다고 가정하던 것을, 어느 쪽이 이기든 하나만 성공하고 행이 하나만 남는지 확인하도록 바꿨다.
- Validation: 수신 주소·현재 상태 판정과 "주소가 그대로면 비교 생략"을 되돌리면 새 테스트 6건과 기존 1건이 실패함을 확인했다.
- Risks: 관리자 회원 수정에서 이메일을 빈 값으로 저장하면 응답 직렬화에서 500이 난다(이번 변경 이전부터 있던 문제, 미수정). 운영 초기 시드(`apps/api/seed_production.py`)는 서비스를 거치지 않고 학번 완전 일치로만 쓴다(운영자 전용 경로).

## 독립 리뷰(Codex) 2차 반영

- Security (P1): 회원 이메일을 고치고 재발급해도, 고치기 전에 옛 주소로 나간 활성화 링크가 72시간 동안 그대로 쓸 수 있던 문제. 토큰에 발급 당시 회원 이메일의 지문을 넣고, 활성화와 발송에서 회원의 현재 이메일과 비교한다. 주소가 바뀌면 그 전에 발급한 링크는 재발급 여부와 무관하게 거절된다. 지문이 없는 이전 버전 토큰은 신청서 이메일 기준으로 판정한다(이전 버전은 신청서 주소로만 보냈다). 스키마 변경 없음.
- Fixed (P2): 승인 직후 자동 발송이 세션에 남은 회원 값을 써 그사이 고쳐진 주소·상태를 놓칠 수 있던 문제. 발송 판정 직전에 회원 행을 다시 읽는다.
- Fixed (P2): "주소가 그대로인 저장"이 소문자로 바꾼 값을 여전히 써, 화면이 읽어 둔 옛 주소로 그사이의 수정을 덮을 수 있던 문제. 주소가 그대로면 이메일 칼럼을 쓰지 않는다(저장된 표기 유지).
- Fixed (P2): 관리자 카드의 "보낼 주소"가 수동 발송 뒤에도 옛 주소를 보이고, 보낼 수 없는 상태에서 신청서 주소를 보이던 문제. 실제 발송 주소를 반영하고, 보낼 수 없으면 "없음"으로 보인다.
- Changed: `issue_activation_token`은 커밋하지 않는다(호출자가 스냅샷 확보 뒤 커밋). 새 오류 코드 `activation_link_outdated`(수동 발송 409).
- Validation: 지문 비교를 끄면 새 테스트가 실패함을 확인했다. 전체 `pytest -q` 554건 통과.

## 독립 리뷰(Codex) 3차 반영

- Security (P1): 활성화가 신청·회원을 잠그지 않고 읽어, 판정 직후 커밋된 이메일 수정·재발급과 무관하게 옛 주소의 링크로 비밀번호를 저장할 수 있던 문제. 활성화가 신청 행 → 회원 행 순서로 `FOR UPDATE` 잠금을 잡고 현재 값으로 판정한다. 비밀번호 저장과 신청 상태 변경을 한 트랜잭션으로 합쳤다(`auth_repo.stage_member_auth`; 이전에는 커밋이 둘이라 둘째가 실패하면 비밀번호가 있는 회원의 신청이 `approved`로 남았다). 쓰이지 않게 된 `create_or_update_member_auth`·`create_member_auth`는 지웠다.
- Fixed (P2): 본인 수정 화면이 고치지 않은 이메일도 항상 보내, 화면을 열어 둔 사이 관리자가 고친 주소를 옛 값으로 되돌릴 수 있던 문제. 저장된 주소와 같으면 이메일을 보내지 않는다(`buildProfilePayload`).
- Fixed (P2): 관리자 카드가 더 쓸 수 없는 링크의 주소·복사·발송 버튼을 계속 보이던 문제. 수동 발송이 `activation_link_outdated`로 거절되면 카드를 재발급 안내로 바꾼다. 회원 이메일이 없을 때는 "이메일 입력 뒤 재발급"으로 안내하고, 다시 보내도 소용없는 실패에서는 발송 버튼을 숨긴다.
- Notes: 링크 판정은 현재 주소와의 일치다. 주소를 A→B→A로 되돌리면 A로 나간 링크는 유효 기간(72시간) 안에서 다시 유효해진다.
- Validation: 활성화 잠금을 끄면 `test_activation_waits_for_uncommitted_email_correction_and_is_refused`가 실패함을 확인했다.
