# 개발 로그 2026-10-13

- Next.js 16.2.11에 걸린 critical 원격 코드 실행 취약점(GHSA-p293-qw3h-jr36, GHSA-2xp9-vwfh-vxw4, GHSA-vcvr-r3jv-pc5j)과 2026-10-07 공개된 Image Optimization SSRF·SSG/ISR 캐시 오염 취약점을 막기 위해 Next.js와 번들 분석기를 `16.3.8`로 올렸다.
- Next.js 16.3.8이 Sharp `^0.35.4`와 PostCSS `8.5.23`을 직접 선택하게 되어 문서의 제거 조건을 충족한 `sharp`·`postcss` workspace override를 제거했다. 워크스페이스 Sharp는 libheif 취약점이 수정된 `0.35.5`로 올렸다.
- PostCSS의 전이 의존성 source-map-js를 lockfile에서 `1.2.2`로 올려 event-loop DoS 취약점을 해소했고, baseline-browser-mapping을 `2.11.28`로 갱신했다(Dependabot #321·#322 대체).
- Sentry를 운영 배포판에 도입했다. Web은 `@sentry/nextjs` 11.7.0으로 브라우저·Node·Edge 오류와 `onRequestError`, 루트 `global-error`를 수집하고, 운영 이미지 빌드에 `NEXT_PUBLIC_SENTRY_DSN`이 있을 때만 켜진다.
- 활성화 토큰이 쿼리스트링으로 오가는 것을 확인해 Web 오류 이벤트·span·이동 기록의 쿼리 값을 모두 가리고, Web 서버는 요청 본문을 첨부하지 않게 했다.
- API Sentry 이벤트에 회원 전화번호가 요청 본문으로, 전화번호와 활성화 토큰이 스택 지역 변수로 평문 전송되던 것을 재현하고 본문·지역 변수 수집을 껐다(회귀 테스트 추가).
- 배포 태그를 API `RELEASE`와 Web Sentry 릴리스로 함께 쓰고, 소스맵 업로드는 빌드 호스트의 `sentry` CLI 로그인 토큰을 빌드마다 갱신해 BuildKit secret으로만 Web 빌드에 넘기도록(wastelite-suite와 같은 방식) 배포 스크립트와 계약 테스트를 갱신했다.
- `@sentry/nextjs`의 빌드 플러그인이 끌어오는 brace-expansion 5.0.7(high DoS 4건)을 lockfile에서 5.0.12로 올려 CI 운영 의존성 audit를 통과시켰다.
