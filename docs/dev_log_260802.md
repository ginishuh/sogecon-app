# Dev Log 2026-08-02

## PR #286 관리자 이미지 전체 삭제 payload 보존

- Root cause: 마지막 이미지를 관리자 편집 화면에서 삭제하면 `MultiImageUpload`가
  `cover_image: null`, `images: []`를 만들지만, `buildPostUpdatePayload`가 이를 각각
  `undefined`로 바꾸어 `JSON.stringify` 결과에서 필드를 제거했다. API의
  `PostUpdate`·repository와 PostgreSQL은 명시적 `null`/`[]`를 이미 삭제 값으로
  지원하므로 서버 계약이 아니라 Web payload helper의 의도 손실이었다.
- Fixed: 관리자 payload helper가 `cover_image`와 `images`를 그대로 전달하도록 수정했다.
  `/admin/posts/{id}/edit`와 `/board/{id}/edit`의 `admin_posts` 경로는 기존처럼 같은
  helper를 사용한다. category/publication 보호 필드와 owner mutation endpoint 계약은
  건드리지 않았고, API/스키마/마이그레이션 변경도 없다.
- Regression coverage: helper의 `null`/`[]` 보존, 두 관리자 편집 화면의 저장 payload,
  API의 기존 이미지 생성 → 명시적 삭제 → admin preview readback을 고정했다. PR CI용
  deterministic mock API에도 이미지 상태를 추가해 관리자 UI에서 두 이미지를 삭제한
  뒤 PATCH body와 mock readback을 확인하는 E2E를 추가했다.
- Automated verification: `pnpm -C apps/web test`는 77 files / 269 tests PASS,
  `pnpm -C apps/web lint` PASS, `NEXT_PUBLIC_WEB_API_BASE=http://127.0.0.1:3001`
  빌드 환경의 `pnpm -C apps/web build` PASS, mock production Web E2E는 5 files /
  11 tests PASS, 관련 API 관리자·owner·D4 권한 테스트는 48 passed PASS였다.
- Real local browser verification: 전용 PostgreSQL `appdb_test`(localhost:5434)에
  저장소 test fixture/model 경로로 `admin,admin_posts,member` 계정과 이미지 게시물
  (post id 1)을 seed했다. 기존 CLI를 `DISPLAY=:0` headed Chrome으로 실행하고
  production Web `127.0.0.1:3000` + real local API `127.0.0.1:3001` + 위 DB만 연결했다.
  실제 관리자 로그인 → `/admin/posts`의 `수정` click → `/admin/posts/1/edit`에서
  두 이미지 삭제로 `이미지 0/10장` 확인 → 저장을 수행했다. 실제 PATCH body는
  `cover_image: null`, `images: []`를 포함했고, API preview와 DB readback 모두
  `cover_image IS NULL`, `images = []`(JSONB array)였다. mock과 storage-state 파일은
  사용하지 않았다.
- Cleanup: local API/Web/browser를 종료하고 `appdb_test`에서 정확한 post id 1과
  `pr286admin` fixture 계정을 삭제했다. 삭제 후 두 row count 모두 0이며 3000/3001
  포트와 PR286 임시 파일도 남기지 않았다. `.agents/skills/playwright-cli`
