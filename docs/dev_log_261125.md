## 학번 형식 제한 철회(실사용 회귀)

- Reverted: 운영에 학번을 기억하지 못해 `기억안남`, `기억안나요 ㅠㅠ`, `경제대학원 2020`처럼 적고 승인된 실제 회원이 있어, 2차 리뷰 D에서 넣은 영문·숫자 제한(`422 invalid_student_id`)과 가입 폼의 같은 검증·문구를 제거했다. `tests/api/test_abc_phase1.py`의 테스트 학번 변경도 되돌렸다.
- Changed: Unicode `lower` 불일치는 비교 규칙으로 막는다. `student_id_key.py` 한 곳에서 입력(앞뒤 공백 제거)이 ASCII면 학번 키로 ASCII 저장 값(`octet_length = char_length`)과만 비교하고, ASCII가 아닌 입력은 원문 완전 일치로만 찾는다. 접수·승인 조회와 advisory lock 이름이 모두 같은 함수(`student_id_match_clause`, `student_id_lock_name`)를 쓴다. 테스트 DB(`en_US.utf8`)에서 PostgreSQL `lower`는 `K`(KELVIN SIGN)→`k`, `İ`→`i`로 바꿔 Python 키와 섞일 수 있음을 확인했고, 저장값 ASCII 제한을 빼면 해당 테스트가 실패한다.
- Decision: 저장은 앞뒤 공백만 제거한다(ASCII도 내부 공백은 유지). 이 작업 전 웹 가입 폼은 `trim()`한 값을 보냈고, 로그인은 저장된 학번과 완전 일치로 비교하므로 내부 표기를 바꾸면 신청자가 입력한 값으로 로그인할 수 없게 된다. 웹에서 들어온 신청은 원래 앞뒤 공백이 없었으므로 웹 사용자에게는 동작 변화가 없고, 직접 API 호출로 들어온 앞뒤 공백만 웹과 같게 맞춘다(로그인 화면은 입력을 trim하지 않아, 앞뒤 공백이 저장되면 그 공백까지 쳐야 로그인된다).
- Validation: `tests/api/test_signup_non_ascii_student_id.py`(한글 학번 접수·승인·메일 발송, 같은 원문 활성 회원 409, 변형 매칭 없음, `İ`·KELVIN SIGN 비교 분리, 잠금 이름 분기). ASCII 분기를 없애면 5건, ASCII 저장값 제한을 없애면 2건 실패함을 확인했다.

- Validation (형식 제한 철회 후): API 515 passed, Web 386 passed, guards·versions·ruff·pyright(0 errors)·githooks 통과, OpenAPI/DTO 재생성 결과는 1차 반영본과 동일. Web build는 다시 실행하지 않았다.
