# 2026-11-15

- Added: 회원 셀프 비밀번호 재설정. `POST /auth/member/password-reset/request`(학번+이메일, 일치 여부와 무관하게 202, 메일은 백그라운드 발송)와 `POST /auth/member/password-reset/confirm`(토큰 + 새 비밀번호)을 추가했다.
- Added: 재설정 토큰은 서버 상태 없이 `itsdangerous` 서명(1시간)으로 검증하고, 발급 시점 비밀번호 해시의 HMAC 지문을 담아 비밀번호가 바뀌면(재설정 완료·비밀번호 변경) 기존 링크가 무효가 된다. DB migration은 없다.
- Added: Web `/forgot-password`, `/reset-password` 화면. 링크 토큰은 주소창에서 지우고, 성공하면 세션을 정리한 뒤 로그인 화면으로 보낸다.
- Changed: 로그인 화면·로그인 실패 안내에 비밀번호 찾기 링크를 연결하고, FAQ의 "재설정 링크 발송"·"5회 실패 시 10분 제한" 문구를 실제 동작에 맞게 고쳤다.
- Ops: `RATE_LIMIT_PASSWORD_RESET`(기본 `10/hour`, IP 기준) 설정 추가. SMTP 미설정 시 요청은 `email_not_configured`(409)로 응답한다.
- Notes: 세션이 서명 쿠키라 재설정·비밀번호 변경 시 다른 기기의 기존 로그인 세션은 끊기지 않는다(기존 비밀번호 변경과 동일한 한계).
- Fixed (Codex 리뷰 반영): 같은 토큰의 동시 확인 요청이 모두 성공하던 경합을 기존 해시 조건부 UPDATE로 막아 한 요청만 성공하게 했다. 비ASCII 이메일 비교에서 `compare_digest` TypeError(500)로 계정 존재가 드러나던 문제를 UTF-8 바이트 비교로 고쳤다. 두 경우 모두 수정 전 실패하는 회귀 테스트를 추가했다.
- Validation: API 464 tests, Web 375 tests, lint/pyright, Web build, OpenAPI/DTO 재생성. 로컬 실제 Web·API·DB + 로컬 SMTP 수신기로 요청→메일→재설정→새 비밀번호 로그인→링크 재사용 거부, 불일치 요청 202·무발송, 동시 확인 1건만 성공, 모바일 375px 레이아웃을 확인했다.
