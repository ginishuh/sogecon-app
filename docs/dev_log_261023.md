# 2026-10-23 Pillow security update

## Scope and evidence

- Follow-up to PR #333: update Pillow 12.3.0 to 13.0.0 after the Python CI audit failure. User authorized compatibility review, tests and push; merge and deployment remain outside scope.
- Official release: https://pillow.readthedocs.io/en/stable/releasenotes/13.0.0.html (2026-10-16), https://github.com/python-pillow/Pillow/releases/tag/13.0.0.
- Example patched advisory: https://github.com/python-pillow/Pillow/security/advisories/GHSA-78g4-xqwv-q3g8 lists affected wheels 11.1.0–12.3.0 and patched 13.0.0.
- CI run 39878894432 and a fresh pip-audit JSON for Pillow 12.3.0 report 35 entries: 34 CVE IDs and one GHSA ID, all with fix version 13.0.0. CVE aliases are not counted again. This is a dependency advisory count, not proof of 35 exploitable application paths.
- The shared upload/avatar pipeline opens untrusted image bytes, checks decoded format and dimensions, then loads, resizes/converts and re-encodes. JPEG/PNG/WebP and post GIF handling overlap relevant decoder/metadata concerns. Other format-specific findings are not automatically reachable; format validation after Image.open is not proof that all parsing risk is excluded.

## Change and compatibility

- Changed apps/api/requirements.txt and its docs/versions.md projection to Pillow==13.0.0. There is no Python lockfile in this repository; pnpm-lock.yaml does not manage Pillow and is unchanged by this follow-up.
- Python 3.12 in CI/production remains supported; Pillow 13 drops Python 3.10.
- No app use of removed fromarray datatype mode overrides, get_child_images, Image._show, ImageCms profile attributes, or ExifTags.IFD.Makernote was found.
- The removed implicit I-mode PNG save conversion was considered. A real encoded 16-bit PNG roundtrip through the pipeline passes under both versions without a compatibility shim.
- No application code, public API, test expectations, or CI policy changes were needed.

- Version guard and full Ruff check of apps/api, tests, ops/ci and scripts: PASS.
- Full requirements pip-audit --strict: PASS, 76 resolved dependencies and zero reported vulnerabilities. pip check: PASS. This is not a claim that the deployed service has been updated or is free of all vulnerabilities.
- API Pyright: PASS, 0 errors and 2 warnings using an external config that only points to the isolated environment. The first invocation used the repository's absent .venv and failed to resolve dependencies; that environment failure is not an application regression.
- Existing tests/api/test_uploads.py, test_upload_protection.py and test_profile_avatar.py cover upload formats, resizing, avatars, invalid data and resource limits. No duplicate permanent tests were added.
- Docker/PostgreSQL are unavailable in this Windows execution environment. The complete PostgreSQL-backed API tests, remaining required gates, web production build and mock E2E are delegated to this PR's existing Linux CI after push. Final results and exact SHA are recorded in the PR description, without treating pending or skipped jobs as passes.
- No live-service attack test, deployment or service restart was performed.

## Upcoming event card banner (local follow-up)

- The homepage upcoming event card always used the bundled networking photo. It now reuses an enabled, image-bearing hero banner for the selected event and falls back to that photo when no such banner exists. Event selection, links and the top carousel are unchanged.
- Multiple eligible banners retain the existing `pinned DESC, updated_at DESC` priority. The card checks the returned target type/ID and public status before using its image.
- Added an optional positive `event_id` filter to the existing public `/hero/` endpoint, its service/repository call and the web service. Filtering occurs before pagination and excludes missing/blank images. The existing public endpoint accepts at most ten slides; scanning only that limited response would incorrectly miss the selected event behind unrelated banners. Calls without the parameter retain the existing behavior. No new endpoint, data model or migration was introduced.
- Regenerated OpenAPI and TypeScript DTOs together; repeated generation produces identical files.
- New web regression cases cover the same event, another event, a post with the same ID, missing/blank image, no banner, unpublished banner, server priority and no upcoming event. The API regression uses eleven higher-ranked unrelated banners and verifies exact event filtering, enabled state, missing images and pinned/recent priority. Removing the filter makes the new regression fail; restoring it passes.
